# Phase 01 Implementation Plan — Knowledge Lane Skeleton

## Objective

Implement the first scalable extension to the QuranAtlas data pipeline: the **Knowledge Lane**.

This phase adds deterministic, build-time generated knowledge artifacts that enrich the reader without making the reader dependent on them.

The goal is to support:

- ayah-level theme tags
- passage grouping
- passage summaries
- theme-to-ayah lookup
- future reflection prompt selection
- future related-ayat features
- future AI/RAG grounding

This phase must **not** introduce AI, embeddings, claim extraction, user personalization, or live generation.

---

# 3. Design Rules

## Rule 1 — Reader independence

The reader must render Arabic and translation even if every knowledge file is missing.

Knowledge loading failures are non-fatal.

## Rule 2 — Per-surah runtime loading

Runtime files should be sharded by surah.

Do not emit one giant knowledge file for all 6,236 ayat except small indexes.

## Rule 3 — Hafs-keyed canonical data

For Phase 01, knowledge data is keyed by standard Hafs-style ayah keys:

```text
2:255
18:10
112:1
```

Riwayah-specific display alignment can use the existing alias resolver later.

## Rule 4 — Controlled taxonomy

Themes must come from `data/taxonomy/themes.json`.

No arbitrary theme strings are allowed in ayah or passage data.

## Rule 5 — Curated only

Phase 01 data should be manually curated or imported from trusted structured sources.

No AI-generated knowledge should enter baseline output unless explicitly marked and reviewed. For Phase 01, avoid AI-generated data entirely.

# 5. Source Schema: `data/taxonomy/themes.json`

## Purpose

Defines allowed theme IDs and their metadata.

## Shape

```json
[
  {
    "id": "guidance",
    "label": {
      "en": "Guidance",
      "ar": "الهداية"
    },
    "parentId": null,
    "aliases": ["hidayah", "being guided"],
    "related": ["taqwa", "revelation"],
    "description": "Allah guiding people to truth, clarity, obedience, and salvation."
  }
]
```

## Required fields

```text
id
label.en
description
```

## Optional fields

```text
label.ar
parentId
aliases
related
```

## Field rules

### `id`

- lowercase kebab-case or lowercase snake_case
- must be globally unique
- examples:
  - `guidance`
  - `taqwa`
  - `sabr`
  - `akhirah`
  - `divine-mercy`

Recommended regex:

```regex
^[a-z][a-z0-9-]*$
```

### `label`

Must include English initially:

```json
"label": { "en": "Guidance" }
```

Arabic label is recommended:

```json
"label": { "ar": "الهداية" }
```

### `parentId`

Must be either:

```json
null
```

or an existing theme id.

### `related`

Every related id must exist in the same file.

# 6. Source Schema: `data/normalized/knowledge/passages.json`

## Purpose

Defines contiguous passage groupings.

A passage is a meaningful ayah range inside one surah.

## Shape

```json
[
  {
    "id": "2:1-5",
    "surah": 2,
    "startKey": "2:1",
    "endKey": "2:5",
    "title": {
      "en": "The qualities of those who receive guidance"
    },
    "summary": {
      "en": "The opening passage describes the people who benefit from the Book."
    },
    "themes": ["guidance", "taqwa", "belief"],
    "roleInSurah": "opening_classification",
    "source": {
      "kind": "curated",
      "reviewStatus": "approved"
    }
  }
]
```

## Required fields

```text
id
surah
startKey
endKey
title.en
summary.en
themes
source.kind
source.reviewStatus
```

## Field rules

### `id`

For Phase 01, use:

```text
{startKey}-{endAyahNumber}
```

Examples:

```text
2:1-5
2:255-255
112:1-4
```

This avoids ambiguity and keeps IDs readable.

### `surah`

Integer from `1` to `114`.

### `startKey` / `endKey`

Must be valid ayah keys in the same surah.

### `title`

Short user-facing title.

Keep under 80 characters where possible.

### `summary`

Short passage summary.

Keep under 280 characters where possible.

### `themes`

Array of theme ids.

Each id must exist in `themes.json`.

### `roleInSurah`

String enum for now.

Initial allowed values:

```text
opening
opening_classification
narrative
command
warning
promise
argument
dua
conclusion
transition
unknown
```

### `source.reviewStatus`

Allowed values:

```text
draft
approved
deprecated
```

Only `approved` should ship in baseline.

# 7. Source Schema: `data/normalized/knowledge/ayah-themes.json`

## Purpose

Maps individual ayat to one or more themes.

## Shape

```json
[
  {
    "ayahKey": "2:2",
    "themes": [
      {
        "id": "guidance",
        "weight": 0.95,
        "source": "curated",
        "certainty": "high"
      },
      {
        "id": "taqwa",
        "weight": 0.85,
        "source": "curated",
        "certainty": "high"
      }
    ]
  }
]
```

## Required fields

```text
ayahKey
themes[].id
themes[].weight
themes[].source
themes[].certainty
```

## Field rules

### `ayahKey`

Must be valid against the existing `surahs.json`/known ayah counts.

### `themes[].id`

Must exist in `themes.json`.

### `themes[].weight`

Number from `0` to `1`.

Suggested meaning:

```text
0.90–1.00 = central theme
0.70–0.89 = strong theme
0.40–0.69 = secondary theme
0.10–0.39 = weak/supporting theme
```

### `themes[].source`

Allowed values:

```text
curated
imported
generated_reviewed
```

For Phase 01 baseline, use:

```text
curated
```

### `themes[].certainty`

Allowed values:

```text
high
medium
low
```

For Phase 01 baseline, prefer:

```text
high
medium
```

Avoid shipping low-certainty tags.

# 8. Generated Output: `public/dataset/knowledge/ayah/{NNN}.json`

## Purpose

Runtime-loadable ayah knowledge for one surah.

## Example

```json
{
  "surah": 2,
  "version": "knowledge-v1",
  "ayahs": [
    {
      "key": "2:1",
      "passageId": "2:1-5",
      "themes": []
    },
    {
      "key": "2:2",
      "passageId": "2:1-5",
      "themes": [
        {
          "id": "guidance",
          "weight": 0.95,
          "certainty": "high"
        },
        {
          "id": "taqwa",
          "weight": 0.85,
          "certainty": "high"
        }
      ]
    }
  ]
}
```

## Rules

- Exactly one object per ayah in the surah.
- Every ayah must appear, even if it has no themes.
- `passageId` may be `null` if the ayah has not yet been assigned.
- Themes should be sorted by descending weight.

## Purpose

## Example

```json
    "guidance": [
      {
        "ayahKey": "1:6",
        "weight": 0.95
      },
      {
        "ayahKey": "2:2",

      }
    ],
    "taqwa": [
      {
        "ayahKey": "2:2",
        "weight": 0.85
      }
    ]
  }
}
```

## Rules

- Include only ayah-theme mappings from approved/allowed sources.
- Sort each theme list by:
  1. descending weight
  2. surah number
  3. ayah number

# 13. Build Script: `scripts/data/build-knowledge-dataset.mjs`

## Responsibilities

The script should:

1. Load existing surah metadata or expected ayah counts.
2. Load `themes.json`.
3. Load `passages.json`.
4. Load `ayah-themes.json`.
5. Validate all source files.
6. Build per-surah ayah knowledge files.
7. Build per-surah passage files.
8. Build indexes.
9. Write generated files under `public/dataset/knowledge/**`.
10. Optionally update or participate in `manifest.json`.

## Recommended implementation structure

```js
const ROOT = process.cwd();

const PATHS = {
  themes: 'data/taxonomy/themes.json',
  passages: 'data/normalized/knowledge/passages.json',
  ayahThemes: 'data/normalized/knowledge/ayah-themes.json',
  outRoot: 'public/dataset/knowledge'
};

async function main() {
  const quranMeta = await loadQuranMeta();
  const themes = await readJson(PATHS.themes);
  const passages = await readJson(PATHS.passages);
  const ayahThemes = await readJson(PATHS.ayahThemes);

  const themeMap = validateThemes(themes);
  validatePassages(passages, quranMeta, themeMap);
  validateAyahThemes(ayahThemes, quranMeta, themeMap);

  const model = buildKnowledgeModel({
    quranMeta,
    themes,
    passages,
    ayahThemes
  });

  await writeKnowledgeDataset(model);
}
```

## Functions to implement

```text
readJson(path)
writeJson(path, value)
parseAyahKey(key)
compareAyahKeys(a, b)
expandAyahRange(startKey, endKey)
loadQuranMeta()
validateThemes(themes)
validatePassages(passages, quranMeta, themeMap)
validateAyahThemes(ayahThemes, quranMeta, themeMap)
buildKnowledgeModel(input)
writeKnowledgeDataset(model)
```

# 15. Validation Details

## Ayah key validation

Input:

```text
2:255
```

Rules:

- contains exactly one colon
- surah is integer `1..114`
- ayah is integer `1..surahAyahCount`
- no leading zeroes in input keys

Valid:

```text
1:1
2:255
114:6
```

Invalid:

```text
001:001
0:1
115:1
2:0
2:999
2-255
```

## Theme validation

Fail if:

- duplicate theme id
- invalid id format
- missing `label.en`
- missing `description`
- `parentId` references missing theme
- `related[]` references missing theme

## Passage validation

Fail if:

- duplicate passage id
- invalid surah
- invalid start/end key
- start and end are in different surahs
- `surah` does not match `startKey`
- end ayah is before start ayah
- any theme id is unknown
- `source.reviewStatus` is not allowed
- baseline build includes non-approved passage

## Passage overlap policy

For Phase 01:

- ayah may belong to zero or one passage
- overlapping passages are not allowed

Fail on overlap.

Later phases can introduce separate thematic collections if needed.

## Ayah-theme validation

Fail if:

- duplicate `ayahKey` entry
- unknown theme id
- invalid weight
- invalid certainty
- invalid source
- empty themes array, unless explicitly allowed

Recommended: omit ayat with no themes from source. The generated output will still emit every ayah.

# 16. Runtime Module: `src/data/knowledge-dataset.ts`

## Types

```ts
export type AyahKey = `${number}:${number}`;

export interface AyahTheme {
  id: string;
  weight: number;
  certainty: 'high' | 'medium' | 'low';
}

export interface AyahKnowledge {
  key: AyahKey;
  passageId: string | null;
  themes: AyahTheme[];
}

export interface AyahKnowledgeSurah {
  surah: number;
  version: string;
  ayahs: AyahKnowledge[];
}

export interface Passage {
  id: string;
  startKey: AyahKey;
  endKey: AyahKey;
  title: Record<string, string>;
  summary: Record<string, string>;
  themes: string[];
  roleInSurah: string;
}

export interface PassageSurah {
  surah: number;
  version: string;
  passages: Passage[];
}
```

## Functions

```ts
export async function loadAyahKnowledgeForSurah(
  surahNumber: number
): Promise<AyahKnowledgeSurah | null>;

export async function loadPassagesForSurah(
  surahNumber: number
): Promise<PassageSurah | null>;

export async function getThemesForAyah(
  ayahKey: AyahKey
): Promise<AyahTheme[]>;

export async function getPassageForAyah(
  ayahKey: AyahKey
): Promise<Passage | null>;

export async function getAyahKnowledge(
  ayahKey: AyahKey
): Promise<AyahKnowledge | null>;
```

## File loading paths

```ts
/dataset/knowledge/ayah/002.json
/dataset/knowledge/passages/002.json
```

Use the same three-digit surah formatting convention as the existing dataset.

## Failure behavior

If a file is missing or fails to parse:

- return `null` for surah loaders
- return `[]` for theme lists
- return `null` for passage lookup
- do not throw into the UI by default

Internal logging is acceptable.

# 26. UX Integration For Phase 01

Keep UX very light.

## Passage label

Display once at the beginning of a passage:

```text
This passage: The qualities of those who receive guidance
```

or:

```text
Guidance · Taqwa · Belief
```

## Ayah interaction surface

When user taps an ayah, show:

```text
Themes
Guidance · Taqwa
```

Do not show:

- long summaries
- AI responses
- all related ayat
- “deep reflection” UI

Phase 01 should feel like gentle context, not a new feature explosion.

---

# 27. Acceptance Criteria

Phase 01 is complete when:

- existing reader still works unchanged without knowledge files
- `pnpm run build:knowledge` emits valid knowledge files
- generated files are under `public/dataset/knowledge/**`
- every emitted ayah file includes all ayat for that surah
- every emitted passage file includes approved passages for that surah
- theme indexes are generated
- runtime loaders safely load knowledge data
- tests cover invalid keys, invalid themes, overlap, and missing runtime files
- UI can optionally show passage title and theme chips
- no AI or reflection prompts are introduced yet

---

# 28. Explicit Non-Goals

Do not implement in Phase 01:

- reflection prompts
- journaling
- AI copilot
- RAG chunks
- embeddings
- tafsir claim extraction
- user personalization
- social/community reflections
- multi-madhhab governance
- detailed fiqh/aqidah guardrails
- complex semantic verse-unit alignment

These belong to later phases.

1. Add taxonomy file.
2. Add passage seed file.
3. Add ayah-theme seed file.
4. Write validators.
5. Write knowledge model builder.
6. Emit per-surah ayah files.
7. Emit per-surah passage files.
8. Emit indexes.
9. Add package scripts.
10. Add runtime loader.
11. Add tests.
12. Add minimal reader UI.
13. Add manifest/offline integration if needed.

This order keeps the refactor controlled and reviewable.
