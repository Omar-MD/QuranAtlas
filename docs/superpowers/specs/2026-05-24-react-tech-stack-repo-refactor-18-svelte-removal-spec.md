# React Tech Stack Refactor 18 - Svelte Removal Spec

  `docs/superpowers/specs/2026-05-24-react-tech-stack-repo-refactor-design.md`

## Purpose

Remove Svelte-only source, dependencies, scripts, generated context entries, and
workflow instructions only after the React production entry has soaked
successfully and rollback no longer requires retained Svelte source.

## Current Docs Requirement

If Svelte removal changes package-manager, Vite, TypeScript, ESLint, Stylelint,
Vitest, Playwright, or CI configuration details beyond already verified
patterns, fetch current docs through Context7 before writing the implementation
plan.

## Scope

In scope:

- Remove Svelte-only source and route modules.
- Remove Svelte-only dependencies and scripts.
- Remove Svelte-only tests after React coverage owns the behavior.
- Remove Svelte-specific docs, context entries, and skills language.
- Regenerate context docs.
- Update tech-stack, architecture, repo-structure, implemented, roadmap, and
  product docs to current React-only reality.
- Preserve data, public assets, source catalogs, and runtime dataset contracts.

Out of scope:

- Removing rollback history from git.
- Changing product scope.
- Deleting source-data or public dataset assets just because Svelte used them.
- Removing compatibility data paths unless a separate data migration spec owns
  it.

## Allowed Files And Directories

Allowed modify or delete:

- Svelte-only source, tests, scripts, dependencies, configs, and generated
  context entries after React coverage owns the behavior.
- Root and scoped AGENTS files, repo-local skills, `docs/tech-stack.md`,
  architecture, repo-structure, implemented/current-state docs, style-map, and
  generated inventories.

Forbidden modify:

- Product scope.
- Source-data contracts, public dataset assets, fonts, icons, or catalog files
  unless a separate data migration spec owns the change.
- Compatibility dataset paths needed by React runtime.
- Git history or tagged rollback artifacts.

## Removal Contract

Remove only files that are Svelte-only. Shared framework-neutral runtime,
dataset, source-data, public assets, tests, and docs remain unless React owns an
equivalent and a verification gate proves the old path is obsolete.

Examples of removal candidates:

- `src/**/*.svelte` after React equivalents are production-owned;
- Svelte plugin/dependency packages;
- `svelte-check` and Svelte ESLint paths;
- Svelte-specific style checks only if React has equivalent checks;
- Svelte-specific context inventory entries regenerated by docs tooling.

Examples of retained paths:

- `data/**`;
- `public/dataset/**`;
- `public/fonts/**`;
- source catalog and dataset scripts;
- framework-neutral runtime modules used by React;
- tests that still verify product contracts against React.

## Deliverables

- Removal of Svelte-only runtime, tests, scripts, dependencies, and configuration.
- Regenerated context docs and updated repo-local skills/AGENTS routing for
  React-only work.
- Updated tech-stack, architecture, repo-structure, implemented/current-state,
  roadmap, product, and style-map docs.
- Verification evidence that React coverage owns all retained product behavior.
- Updated rollback policy based on git history or a tagged release rather than
  retained Svelte source.

## Acceptance Criteria

- No Svelte runtime source remains in active production paths.
- Package scripts and dependencies no longer reference Svelte tooling.
- React validation covers all retained product behavior.
- Generated context docs are regenerated and clean.
- `docs/tech-stack.md` describes the React-only current stack.
- Data/source contracts remain intact.
- Rollback policy is updated to rely on git history or a tagged release, not
  retained Svelte source.

## Verification

Run full validation:

```bash
pnpm run docs
pnpm run validate
pnpm run validate:react
pnpm run docs:check
git diff --check
```

If data paths or dataset scripts changed, also run:

```bash
pnpm run data -- check
```

Expected result:

- Full validation passes.
- Generated docs are clean.
- No stale Svelte references remain outside historical docs where intentionally
  retained.

## Rollback And Failure Handling

- If React coverage gaps appear, stop removal and add React proof before
  deleting more Svelte code.
- If package cleanup breaks validation, restore the dependency until the
  replacement check exists.
- If generated docs retain stale Svelte references, fix source annotations or
  inventories and rerun docs generation.

## Handoff

After this spec, React is the only active app implementation. Future QuranAtlas
work should route through React source, React design-system registry, React
tests, and updated repo-local skills.
