# QuranAtlas Settings Overlay Design Brief — `#/settings` (alias `#/assets`)

**Status:** Director design brief (per-screen, v2 part 2). Binding only after orchestrator vetting against spec §6.
**Date:** 2026-09-08
**Route family:** `#/settings` and `#/assets` (alias: same overlay, `initialAssetsExpanded=true`). Rendered as a `Sheet variant="adaptive-settings"` over the current base — a Tier-A reader base (`#/s/…`, `#/m/…`) or a Tier-B ChromeFrame base (`#/surahs`, `#/bookmarks`, `#/search`, `#/about`). Not a routed page; the overlay owns no `<header>` and no drawer host.
**Consumes:** `docs/superpowers/specs/ui/2026-09-08-brief-commonality.md` (chrome tiers §2, ownership/state map §3, theme/night §4, motion §5). **No new tokens, colors, easings, or namespaces.** The one *value decision* this brief makes (the dark scrim) is expressed entirely as existing-token values.

**Evidence base.** Live inspection of `http://127.0.0.1:5173`: overlay opened from the reader gear (`#/s/1`, event path) and the ChromeFrame gear (`#/surahs`, hash path), at 1280×900 and 375×812, in light / sepia / dark (+ dark+night). Exercised live: theme-radio persistence round-trip (dark survived reload), Escape + close-button focus return to trigger, `#/assets` alias (assets expanded), mushaf-mode variant (from `#/m/1` → `#/settings`), mobile scroll, reduced-motion, CSSOM layer ordering. Sources: `src/design-system/tokens/semantic.css` (settings family :56-70, scrim :54 + dark :171, swatches :78-80), `src/design-system/index.css` (adaptive-settings 1498-1890), `src/components/ui/{overlays,form-controls}.tsx`, `src/components/settings/{SettingsShell,SettingsGroup,ThemeNightControls,VerseSettings,MushafSettings,IncludedAssetsSection}.tsx`, `src/app/App.tsx:45-263`, `src/app/routes/settings/{SettingsRoute,AboutRoute,useClearDataDialog}.tsx`.

**Root-cause correction to commonality D2.** D2 says the adaptive-settings bg/shadow/shape failure "needs a correctness look." **Root-caused here.** The live sheet (all themes, both viewports) computes **base-`Sheet` utility** values — bg `canvas`, `shadow-lg`, z `50`, `display:grid`, `padding:20px`, desktop `width:448px` (`w-96`), `border-radius:12px`, `transition:all` — while every `[data-sheet-variant="adaptive-settings"]` declaration (index.css:1503-1520) is **losing the cascade**. Cause: Tailwind v4 `@import "tailwindcss"` inlines its `@layer theme, base, components, utilities` statement **before** the author's `@layer qa-react-reset, qa-react-tokens, qa-react-base, qa-react-components` (index.css:1, `tailwind-theme.css:1`). Layer order is fixed at first declaration, so `utilities` outranks **all** qa-react layers. The base Sheet classes are utilities; the authored variant block sits in `components` (with *lower-specificity* selectors than the variant block), so the utilities win. **Consequence: D2 is not just bg/shadow.** The rail width (`min(28rem,…)`, :1850-1856), `z-index:120`, `inset`, flex column, radius-0, border-0, and the header-sticky offset are **all silently lost**. The whole adaptive-settings restyle must be re-founded so it actually applies — see S-P2.

## 1. Composition (target — commonality language)

The overlay is `Sheet variant="adaptive-settings"` (registry `sheet`, already a declared variant) hosting a `SheetBody.qar-react-settings-shell`. It composes over whichever base is active (Tier A or Tier B) and is **modal**: a scrim (`--qa-react-scrim`) plus a sheet at z-120 over the scrim's z-110. It owns no chrome; the base's chrome (Tier A or Tier B) stays mounted beneath the scrim.

**Structure (open state), top → bottom:**
1. **Sticky header** (`[data-sheet-variant="adaptive-settings"] > div:first-child`, index.css:1523-1542): fill `--qa-react-settings-header`, hairline `border-bottom: --qa-react-settings-divider`, `min-height: env(safe-area-inset-top) + 44px`, title "Verse settings"/"Mushaf settings" + a `CloseButton` (min 44×44, :1543-1546).
2. **Scrolling body** (`.qar-react-settings-body`): `overflow-y:auto`, `overscroll-behavior:contain`, fill `--qa-react-settings-sheet`, grid of `SettingsGroup` cards spaced `--qa-react-settings-space-4`.
3. **SettingsGroup card** (registry `settings-group`, `.qar-react-settings-group`, :1575-1581): `border: 1px solid --qa-react-settings-group-border`, `radius-surface`, fill `--qa-react-settings-group`; heading block (title + description) separated by a `--qa-react-settings-divider` hairline.

**Groups in order** (`SettingsRoute.tsx:120-145`): mode panel (`VerseSettings` = Font size / Reading flow / Translation, *or* `MushafSettings` = Navigation mode / Fit width / [Qur'an text size]) → Reading continuity (Daily Wird) → Appearance (`ThemeNightControls`) → Included reading assets (`IncludedAssetsSection`). An optional write-error banner (see §3) sits above the groups.

**Control ownership (commonality §3.1, all registry primitives — none hand-rolled):**
- Reading flow → `Select` (`form-controls.tsx`); popup portals at z-130 (index.css:217), above the z-120 sheet.
- Translation / Fit width / Daily Wird → `Switch` (not Checkbox).
- Font size / Qur'an text size → `Slider` (labelled, numeric).
- Navigation mode → `SegmentedControl` (`role=radiogroup`, never pill buttons).
- Theme / Night mode → `Button role="radio"` appearance choices (`.qar-react-settings-appearance-choice`, :1793-1812) — **not** `SegmentedControl`, because each option carries a swatch + icon. This is the one sanctioned non-segmented radio set.
- Clear-data (About only) → `Dialog` (`overlays.tsx`) + `Input` + `Button`s.

**Surface recipe (all `--qa-react-settings-*` derive from the shared families; semantic.css:56-70):** sheet = `--qa-react-settings-sheet` (= `--qa-react-sheet`); header = sheet/surface mix; group = surface/sheet mix with an accent-tinted border; divider = group-border at 58%; selected = 15% accent over group; selected-text = `--qa-react-accent-strong`; muted = `--qa-react-text-muted`; elevation = `--qa-react-settings-shadow` (deeper in dark, semantic.css:170).

## 2. Defects seen (each cited)

### Blocking
_None — the overlay always opens, scrolls, and closes with focus return._

### Major
- **S-D1 — Dark-theme scrim is a light warm-gray fog, not a dim.** `#/s/1` dark, both viewports. Live scrim computes `oklab(0.894 0.00004 0.00002 / 0.3)` ≈ `#dcdcdc` at 30% — the *dark-theme text color* — because the overlay carries the utility `qar:bg-text/30` (overlays.tsx:155). The authored token override `background: var(--qa-react-settings-backdrop)` (= `--qa-react-scrim` = `rgb(0 0 0 / 48%)` in dark, semantic.css:56 + :171) **loses the same layer war as D2**: it sits in `components` (index.css:1498-1501) while `bg-text/30` is a `utilities` layer rule. Net: in dark the reader is not dimmed but *washed out*; contrast of underlying text collapses. K2.6's "dark scrim too dark/opaque, reader nearly invisible (48% black)" **conflated the token definition with the render** — the *authored* 48% black never paints; the *actual* defect is a 30% light fog (visibility is hurt far worse than K2.6 assumed). K2.6 is upheld as **major**, with the cause corrected. Fix = S-P1 (token adoption + value decision).
- **S-D2 — Settings opened from a ChromeFrame base teleports the user to the reader.** `#/surahs` → ChromeFrame gear → (close) → user is on `#/s/1`. `App.tsx`: the hash path (`:139-152`) resolves the base through `resolveSettingsPreviousHash` (`:243-252`), which accepts **only** `isReaderHash` (`:254-256`), falling back to `lastReaderHash`/lastSurface/`#/s/1`. A non-reader base is dropped, the hash is replaced with the reader hash, the base remounts to the reader, and `closeSettingsOverlay` (`:169-176`) + `onCloseAutoFocus` land the user on the reader with focus on `reader-settings-trigger` (overlays.tsx fallback) — **not** the `#chrome-settings-trigger` they pressed. Behavioral sweep's "reload at `#/settings` falls through to last-surface continuity" is correct for **reload**, but this is an **open-from-ChromeFrame** navigation hijack. Fix = S-P4.
- **S-D3 — The base's fixed chrome paints over the settings sheet.** Mobile (375×812, reader base) and confirmed in DOM on desktop. The sheet computes `z-index:50` (base `Sheet` utility; the authored `z-index:120` at :1506 is lost to the layer war) while Tier-A reader chrome is `z-index:95` (index.css:1894). The reader chrome bar (nav + title + view-toggle + gear) therefore renders **above** the full-bleed mobile sheet, occluding the sheet's own header; the sheet header is pushed down (`y=21`) and its "Verse settings" title collides with the chrome. Fix = S-P2 (the variant's z-120/restyle must actually apply).
- **S-D4 — The full D2 package: sheet tone, elevation, rail width, radius, and header offset are all inert.** All themes, both viewports. Sheet computes `canvas` bg + `shadow-lg` (not `--qa-react-settings-sheet` + `--qa-react-settings-shadow`); desktop width `448px` (base `w-96`) not `min(28rem, 100vw-24px)`; radius `12px` not `0`; `padding:20px`, `display:grid`, `gap:16px`, `transition:all` from the base utility instead of the flex/radius-0/padding-0 variant (:1503-1520). This is the same root cause as S-D1/S-D3 (layer order). One fix resolves all three: S-P2.

### Minor
- **S-D5 — Mobile full-bleed sheet shows no scroll affordance.** 375×812, all themes. Body scrolls (`scrollHeight 849 > clientHeight 693`) but the sheet is full-bleed `100dvh` with the scrim invisible behind it, so nothing reads as "overlay" or "more below"; the bottom group is clipped mid-card with no shadow/cue. K2.6's "mobile panel cut off with no scroll hint" — **confirmed minor**. Fix = S-P7.
- **S-D6 — Settings write-error banner is a hand-rolled red box, not `Status`.** `SettingsRoute.tsx:122-136` renders `<div role="alert" class="qar:flex … qar:border-danger qar:bg-surface qar:p-3">` + a secondary Retry `Button`. Commonality §3.2 requires `Status tone="error"` (`role=alert`) with a recovery action; this bypasses the owned pattern. Fix = S-P5.
- **S-D7 — Orphaned mushaf rule inside the settings block.** `.qar-react-mushaf-page-actions > button { …48px… }` (index.css:1536-1542) sits between the adaptive-settings header rule (:1523) and the header-button rule (:1543). It is scoped to the mushaf dock (no settings consumer) and does not belong in this block; its `inline-size/block-size:48px` may also fight the dock's own sizing (index.css:3505-3517). Fix = S-P8 (relocate).

## 3. States (single prescription each)

- **Open / ready:** composition per §1. Sheet fill `--qa-react-settings-sheet`, elevation `--qa-react-settings-shadow`; scrim `--qa-react-scrim`. Base chrome (Tier A/B) stays mounted under the scrim.
- **Loading (asset inventory):** `.qar-react-settings-assets` sets `aria-busy` while rows resolve; rows render with label `"Loading asset name"` then swap to real labels. Acceptable inline-loading; the section is a read-only inventory, not a blocking gate, so no `Spinner` is required. Keep.
- **Write error (`settingsWriteError`):** → `Status tone="error"` (`role=alert`, assertive) titled with the error, action slot = `Button size="sm" variant="secondary"` "Retry"/"Saving…" (`disabled` while `settingsWriteStatus==='saving'`). **Replaces the hand-rolled div** (S-D6 / S-P5).
- **Mushaf framing write error (`framingWriteStatus==='error'`):** inline `<p role="status">` (polite) + secondary Retry `Button` (MushafSettings.tsx:83-90). Correct — a recoverable non-blocking save failure belongs polite, not assertive. Keep.
- **Selected — theme / night choice:** `.qar-react-settings-appearance-choice[aria-checked="true"]` → `background: --qa-react-settings-selected`, `border-color: --qa-react-accent-strong`, `color: --qa-react-settings-selected-text` (:1809-1812). Not color-only (border + bg + `aria-checked`). Keep.
- **Selected — SegmentedControl (nav mode):** `qar-react-segmented-option--selected` → `--qa-react-nav-control-selected-bg` + accent text (commonality §3.2). Keep.
- **Checked — Switch:** accent track fill (`data-[state=checked]:bg-accent`) + thumb translate. Not color-only (position + `role=switch` state). Keep.
- **Range fill — Slider:** `Range` `bg-accent` over `Track` `bg-border`; thumb 20px with `shadow-sm`. Value is also shown as a text label ("Medium", "Standard") so the position is never the sole signal. Keep.
- **Swatch (theme target):** `.qar-react-settings-theme-swatch[data-swatch=…]` always fills the *target* theme's `--qa-react-theme-swatch-*` regardless of active theme (:1832-1841). Keep — this is the correct "preview" semantic.
- **Disabled:** `opacity-55 + pointer-events-none` (commonality §3.2) on the clear-data confirm until `canConfirm` (AboutRoute) and on the Retry button while saving. Keep; never color-only.
- **Focus-visible:** `outline: 2px solid --qa-react-focus; outline-offset: 2px` on every control (Select, Switch, Slider thumb, appearance choices, close button, asset toggle). Verified the ring is present on real keyboard focus (programmatic `.focus()` does not set `:focus-visible` — the K2.6 "thin/absent ring" pattern is the same false positive adjudicated in the reader brief). Keep; no inset `-2px` needed (no clipping container).
- **Empty (asset inventory):** the default profile always yields ≥1 row, so no empty state is reachable today; if a profile ever returns zero rows, render `Status tone="info"` "No assets bundled with this profile." (Reserved; do not hand-roll.)
- **Clear-data confirmation (About only):** `Dialog` centered over the shared scrim, `initialFocusRef` on Cancel, `Input` "Type DELETE to confirm", confirm `Button variant="danger"` disabled until `canConfirm`, error `role=alert`. Composes correctly on registry primitives. Keep.

## 5. Prescriptions (commonality language; zero aesthetic gaps)

**S-P1 — Route the scrim through `--qa-react-scrim` and fix the dark value (fixes S-D1; resolves K2.6).** Two parts:
- (a) *Token adoption (shared with commonality D1):* the base `Sheet` overlay must consume `var(--qa-react-scrim)`, not `qar:bg-text/30` (overlays.tsx:155). The settings-specific `:has()` override (:1498-1501) and its z-110 bump stay, but must be expressed so they actually win the cascade (S-P2). After adoption the scrim is token-neutral black in all themes, never text-colored.
- (b) *Dark value decision:* set the dark `--qa-react-scrim` (semantic.css:171) to **`rgb(0 0 0 / 38%)`** — down from 48%, up from the 32% used in light/sepia. Rationale: 48% over the near-black dark canvas (`#0f1215`) flattens the base to unreadable (K2.6's complaint, once the token actually applies); but the dark base's *light* ink (`--qa-react-text #dcdcdc`) needs more dimming than the light base's dark ink to read as "behind" the sheet — so dark sits *between* the light value and its current 48%. Three-theme values: light `rgb(0 0 0 / 32%)`, sepia `rgb(0 0 0 / 32%)`, dark `rgb(0 0 0 / 38%)`. No new token; only the existing dark override value changes. **This is the brief's single value decision; final rendered judgment belongs to the ui-visual-reviewer.**

**S-P2 — Re-found `adaptive-settings` as a real `Sheet` variant so its recipe applies (fixes S-D2-css/S-D3/S-D4; Phase-C remainder).** The entire `[data-sheet-variant="adaptive-settings"]` block (index.css:1498-1890) loses to base-`Sheet` utilities because of the layer-order bug (§D2 root cause). Make the variant a first-class composition on the `Sheet` primitive (registry `sheet` already declares `adaptive-settings`): the variant must *set*, not fight, the fill/elevation/shape. Concretely, the variant recipe must own — with no base utility overriding — `background: --qa-react-settings-sheet`, `box-shadow: --qa-react-settings-shadow`, `z-index: 120`, desktop `inset: 0 0 0 auto; width: min(28rem, 100vw - 24px)`, `border-radius: 0`, `border: 0` (+ `border-inline-start` on desktop), `display: flex; flex-direction: column; padding: 0`, and the sticky header offset. The implementation mechanism (drop the base utilities for this variant, or scope them, or layer-correct) is the implementer's choice; **the acceptance is the computed values above, in all three themes, both viewports.** The overlay scrim-side effect (S-P1a) is the same cutover.

**S-P3 — Keep the reader gear on the event path.** `ReaderPageShell.tsx:124-127` uses `requestReactSettingsOverlay(mode, 'reader-settings-trigger')`, preserving the in-memory base + return focus — correct. No change.

**S-P4 — Preserve the active base when opening from a ChromeFrame surface (fixes S-D2).** `App.tsx` hash-path `openSettingsOverlay` (:139-152) must resolve `previousHash` to **the current hash when it is a valid base**, not only `isReaderHash`. Extend the base guard in `resolveSettingsPreviousHash` (:243-252) / `isReaderHash` (:254-256) to treat ChromeFrame surfaces (`#/surahs`, `#/bookmarks`, `#/search`, `#/about`) as valid bases so the overlay opens *over* `#/surahs` and closes back to it. Pair with focus: `onCloseAutoFocus` (overlays.tsx) must prefer the actual invoker — when opened from ChromeFrame, return focus to `#chrome-settings-trigger`, not the `reader-settings-trigger` fallback. Add `chrome-settings-trigger` to the `targetIds` preference list ahead of the reader fallback. (The `#/surahs` host `NavigationRouteHost.tsx:12-14` may keep its `window.location.hash = '#/settings'` trigger; the fix is in base resolution + focus targets, not the trigger mechanism.)

**S-P5 — Replace the hand-rolled write-error banner with `Status` (fixes S-D6).** `SettingsRoute.tsx:122-136` → `Status tone="error"` (`role=alert`) with the message as title and the existing secondary Retry `Button` in the action slot. No new tokens.

**S-P6 — Hold control sizing; optional icon refinement.** Select (44px), Switch (44px root / 44×24 track), appearance choices (44px+ box), Slider (44px hit / 8px track / 20px thumb) all meet the 44px rule — **no target changes**. The ~19px theme/night icons and 20px swatches are the *visual* affordance within compliant boxes (K2.6 minor, adjudicated cosmetic). Optionally raise the appearance icon from 19px to 20px for optical parity with the swatch — a one-token-free literal, left to implementer taste; not a defect fix.

**S-P7 — Give the mobile full-bleed sheet a scroll affordance (fixes S-D5, minor).** On `@media (max-width:767px)`, add a bottom cue on `.qar-react-settings-body`: a 1px `--qa-react-settings-divider`-colored inset shadow at the body's bottom edge (e.g. `box-shadow: inset 0 -1px 0 var(--qa-react-settings-divider)`), and rely on the first group peeking above the fold (already true at 812px). Do not add a scrollbar-styled element or new motion. Judgment of "enough" belongs to the ui-visual-reviewer; the constraint is: token colors only, no new tokens, no animation.

**S-P8 — Relocate the orphaned mushaf rule (fixes S-D7, cleanup).** Move `.qar-react-mushaf-page-actions > button { …48px… }` (index.css:1536-1542) out of the adaptive-settings block to the mushaf dock region (index.css:3505-3517). No value change.

**S-P9 — Static-audit remainders (no defect; record decisions).** (i) `[data-swatch]` scope (:1832-1841): keep the values; only relax the `.qar-react-settings-shell` prefix if a second consumer (drawer appearance strip) lands — do not pre-emptively globalize. (ii) Appearance selected state (:1809-1812): correct, no `!important`; keep. (iii) The "adaptive-settings via ~20 `!important`" static finding is **void** (zero `!important` exist); the genuine Phase-C work is S-P2's variant cutover.

**No change** prescribed for: theme-radio persistence (works), Escape/close-button focus return (works, modulo S-P4's ChromeFrame target), `#/assets` alias expansion (works), mushaf framing gating (correctly hidden when `hasValidFraming` false), Reading-flow select width (`min-width:10rem` desktop / full-width mobile), night-mode treatment (orthogonal `.qar-react-night-shift` wash; commonality §4), focus rings.

## 6. Motion / reduced-motion

- **Sheet open/close:** today the adaptive-settings sheet has **no entry animation** — the only sheet keyframe, `qar-react-drawer-in` (index.css:1479-1484), is navigation-drawer-only. The base `Sheet` carries a raw `transition: all` (Tailwind preflight) with no property ever transitioning, so the sheet appears instantly. Per commonality §5.1 this is a **structural-settle** surface and *may* take `--qa-react-transition-settle` (240ms, `cubic-bezier(0.2,0,0,1)`). **Prescription:** keep appearance instant (no slide) — the settings overlay is a utility surface, and the nav drawer already owns the slide-in idiom; introducing a competing sheet animation would fork the overlay language. If the implementer finds the instant appearance jarring, a **scrim opacity fade only** (micro-feedback, `--qa-react-transition-fast` 120ms) is the sole permitted motion — never a sheet translate. Default: no new motion.
- **Scrim fade:** scrim appearance/disappearance is a micro-feedback fade at `--qa-react-transition-fast` (120ms). No raw `ms`.
- **Control transitions:** appearance-choice `transition: var(--qa-react-transition-fast)` (:1808) — token-backed, inherits the 1ms collapse. Keep. Switch thumb `transition-transform` and Slider are instant state changes.
